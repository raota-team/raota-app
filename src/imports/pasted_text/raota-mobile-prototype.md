현재 선택한 Figma 프레임 `라오타 MVP · Mobile HIFI v2`를 시각적 기준으로 사용해 RAOTA 모바일 앱의 하이파이 인터랙티브 프로토타입을 확장해줘.

기존 7개 화면을 다른 스타일로 다시 디자인하지 말고, 현재 하이파이의 브랜드 정체성, 정보 밀도, 사진 사용 방식, 하단 내비게이션, 컴포넌트 형태를 유지하면서 화면 사이에 빠진 상태와 인터랙션을 보완해줘.

목표는 정적인 화면 모음이 아니라 사용자가 아래 핵심 흐름을 처음부터 끝까지 실제로 눌러볼 수 있는 완성도 높은 모바일 앱 프로토타입을 만드는 것이다.

`취향에 맞는 라멘 발견 → 가게 판단 → 방문 후 20초 기록 → 내 취향 업데이트 → 다음 추천이 더 정확해짐`

────────────────────
1. 제품 정의
────────────────────

RAOTA는 단순한 라멘 맛집 지도나 별점 리뷰 앱이 아니다.

사용자가 먹은 라멘을 짧게 기록할수록 국물, 면, 간, 토핑 취향이 선명해지고 다음 한 그릇을 더 쉽게 고를 수 있게 해주는 개인 라멘 취향 앱이다.

사용자는 한 번의 세션에서 다음 세 가지를 이해해야 한다.

- 지금 내 취향에 잘 맞는 라멘집이 어디인지
- 왜 이 가게와 메뉴가 내 취향에 맞는지
- 기록 하나가 내 취향과 다음 추천을 어떻게 바꾸는지

평점, 전체 인기 순위, 의미 없는 AI 문구보다 사용자의 실제 기록과 취향 근거를 우선해줘.

이번 프로토타입은 로그인된 기존 사용자 `뿡님`의 한 세션을 기준으로 제작한다. 온보딩, 로그인, 설정 전체, 회원가입, 결제, 예약, 복잡한 커뮤니티 글쓰기는 이번 범위에서 제외한다.

────────────────────
2. 디자인 기준
────────────────────

디자인 우선순위는 다음과 같다.

1. 모바일 화면 구조와 분위기는 현재 선택된 `Mobile HIFI v2`를 최우선 기준으로 삼는다.
2. 브랜드 컬러와 타이포그래피는 RAOTA 디자인 시스템을 따른다.
3. 기존 프레임과 아래 지침이 충돌하면 기존 프레임의 시각적 정체성을 우선한다.

컬러:

- RAOTA Red: #E60000
- Charcoal: #25282B
- Canvas: #FFFFFF 또는 매우 옅은 웜그레이
- Quiet Surface: #F2F2F2
- Divider: 낮은 대비의 웜그레이
- 보조 텍스트는 WCAG AA 대비를 확보한 중간 회색

타이포그래피:

- 기본 서체는 Pretendard
- 화면 제목은 약 22–28px
- 섹션 제목은 18–22px
- 카드 제목은 15–18px
- 본문은 14–16px
- Do Hyeon과 디스플레이 서체는 홈의 짧은 브랜드 문구처럼 특별한 순간에만 제한적으로 사용

시각적 성격:

- 실제 라멘과 매장 사진을 가장 강한 감성 요소로 사용
- 따뜻하고 먹음직스러운 음식 근접 사진과 매장 분위기 사진 사용
- 무거운 그림자 없이 사진, 타이포 위계, 간격, 1px 구분선으로 영역 구분
- 카드와 사진은 6–8px 정도의 절제된 모서리
- 폼과 유틸리티 컨트롤은 더 단정하고 작은 모서리
- 필터 칩과 태그처럼 이유가 있는 요소만 pill 형태 사용
- 한 화면의 한 뷰포트에서 가장 강한 빨간 CTA는 하나만 사용
- 레드는 핵심 행동, 선택 상태, 현재 탭, 중요한 취향 변화에만 사용

다음 스타일은 사용하지 않는다.

- 그라디언트, 글래스모피즘, 네온, 3D 오브젝트
- 과도한 블러, 커다란 그림자, 떠 있는 카드
- 모든 영역을 둥근 카드로 감싼 bento dashboard
- 카드 안의 카드가 반복되는 구조
- 모든 버튼과 입력창을 pill로 만드는 디자인
- 거대한 마케팅 히어로와 서비스 통계
- 일본 전통 붓글씨, 욱일 문양, 노렌, 만화풍 장식
- 의미 없는 AI 배지와 “AI로 더 스마트하게” 같은 홍보 문구
- 이모지를 아이콘 대신 사용하는 방식
- 별점과 전체 순위를 제품의 핵심 가치처럼 강조하는 구성
- 햄버거 메뉴, 웹사이트형 헤더, 푸터, 데스크톱 웹을 축소한 내비게이션

────────────────────
3. 앱 셸
────────────────────

기준 화면은 390×844이며 360–430px 너비에서도 자연스럽게 작동해야 한다.

하단에는 safe area를 포함한 고정 탭 바를 유지한다.

탭 구성:

- 홈
- 지도
- 중앙 `+ 기록`
- 피드
- 마이

중앙 기록 버튼은 가장 중요한 행동으로 분명하게 보이되 콘텐츠를 가릴 정도로 크지 않게 한다.

현재 탭은 아이콘과 텍스트를 함께 RAOTA Red로 표시하고, 비활성 탭은 차콜 또는 회색으로 표현한다.

홈에서는 RAOTA 로고와 최소한의 알림 액션만 보여준다. 상세 화면에서는 뒤로가기, 저장, 공유처럼 해당 화면에 필요한 액션만 보여준다.

────────────────────
4. 확장할 화면과 상태
────────────────────

기존 7개 화면을 기반으로 아래 화면과 상태를 추가해 하나의 프로토타입으로 연결해줘.

### 01. Home / Personalized Discovery

기존 홈의 구조를 유지하되 다음 상태를 더 정교하게 디자인한다.

- 인사: `안녕하세요, 뿡님`
- 메인 질문: `오늘은 어떤 한 그릇이 당기세요?`
- 오늘의 추천 가게와 추천 이유
- `뿡님을 위한 추천`
- `내 주변 라멘`
- `관심 가게 소식`
- 추천 카드 좌우 스와이프
- 추천 카드 선택 시 가게 상세로 이동
- 기록 완료 후 홈으로 돌아왔을 때 취향 추천이 갱신된 상태

추천 이유는 숫자만 보여주지 말고 자연어 설명을 함께 사용한다.

예시:

`최근 진한 국물과 단단한 면을 자주 기록해서 잘 맞을 가능성이 높아요.`

### 02. Map / Ramen Atlas

기존 지도 화면 안에서 다음 상태를 모두 설계한다.

- 기본 지도
- 검색어 입력 중
- 필터 선택 상태
- 현재 위치 표시
- 핀 선택 상태
- 선택된 핀과 하단 가게 카드의 동기화
- 하단 가게 카드 좌우 스와이프
- 검색 결과 없음
- 위치 권한 거부
- 지도 로딩 실패

지도 핀을 선택하면 지도 중심, 선택 핀, 하단 가게 카드가 동시에 바뀌어야 한다.

위치 권한이 거부되면 앱 사용을 막지 말고 서울 기본 위치를 보여준 뒤 다음 액션을 제공한다.

- `위치 다시 불러오기`
- `목록으로 계속 찾기`

### 03. Shop Detail / Decision

기존 가게 상세의 정보 구조를 유지하면서 방문 결정을 더 빠르게 만들도록 다듬는다.

포함할 정보:

- 음식 사진 갤러리
- 가게명, 지점, 라멘 스타일
- 영업 상태와 라스트오더
- 거리와 주소
- 길찾기
- 대표 메뉴와 가격
- 내 취향과 맞는 이유
- 최근 라오타 유저의 한 그릇
- 영업시간, 휴무, 대기 정보
- 저장, 공유

하단 고정 액션:

- `가고 싶어요`
- `라멘 기록하기`

`가고 싶어요`를 누르면 선택 상태와 `가고 싶은 곳에 담았어요.` 토스트를 보여준다.

`라멘 기록하기`를 누르면 현재 가게가 미리 입력된 기록 화면으로 이동한다.

### 04. Record Entry Bottom Sheet

하단 중앙 `+ 기록` 버튼을 누르면 바로 긴 폼으로 이동하지 말고 기록할 가게를 빠르게 선택하는 바텀시트를 연다.

선택지:

- 현재 위치에서 찾기
- 최근 본 가게
- 가고 싶은 곳
- 가게 이름 검색

최근 본 가게로 `멘야준`을 표시하고 선택 시 `특제 쇼유 라멘` 기록 화면으로 연결한다.

### 05. Record / 20-second Log

기록은 긴 리뷰 작성 화면이 아니라 약 20초 안에 완료할 수 있는 한 화면의 빠른 기록이어야 한다.

기본 데이터:

- 가게: `멘야준 · 망원`
- 메뉴: `특제 쇼유 라멘`
- 방문일: 오늘
- 현재 기록 수: 22개

필수 항목:

- 전체 만족도
- 국물
- 면
- 토핑
- 재방문 의사

선택 항목:

- 사진 추가
- 짧은 메모
- 공개 여부

구현할 상태:

- 필수값이 비어 있는 초기 상태
- 메뉴 선택 바텀시트
- 사진 추가 후 미리보기
- 선택된 맛 점수
- 완료 버튼 비활성
- 필수값 완료 후 활성
- 저장 중
- 저장 실패
- 재시도
- 작성 중 뒤로가기 시 유실 확인

맛 점수의 작은 점이나 별은 장식으로만 두지 말고 행 전체를 누를 수 있게 한다. 선택 결과는 `4/5`처럼 숫자로도 보여준다.

저장 실패 시 입력한 값과 사진을 유지하고 `다시 저장하기`를 제공한다.

### 06. Record Complete / Taste Update

기록 완료를 단순 토스트로 끝내지 않는다.

순서대로 보여줄 내용:

1. `22 → 23번째 라멘`
2. 기록한 음식 사진과 가게·메뉴
3. 이번 기록으로 달라진 취향
4. 개인화된 한 줄 인사이트
5. 다음 행동

예시 변화:

- 진한 국물 +1.2
- 단단한 면 +0.8
- 매운맛 -0.1

인사이트:

`진한 동물계 육수와 단단한 면을 특히 선호하고 있어요.`

CTA:

- `내 취향 보기`
- `홈으로`

`내 취향 보기`는 새로 추가할 취향 상세 화면으로 연결한다.

### 07. My / Ramen Life

기존 마이 화면을 유지하되 방금 저장한 기록이 실제로 반영된 상태를 디자인한다.

- 기록 수가 22에서 23으로 변경
- 최근 라멘로그 첫 번째에 `멘야준 · 특제 쇼유 라멘` 추가
- 새 기록 카드를 잠시 강조
- 내 취향 요약
- 자주 먹은 스타일
- 저장한 가게
- 가고 싶은 곳
- 취향 상세 보기

### 08. Taste Detail / My Ramen Identity

RAOTA를 일반 맛집 앱과 구분하는 새로운 핵심 화면이다.

포함할 내용:

- 취향 캐릭터명: `진한 돈골파`
- 핵심 설명: `진한 동물계 육수와 단단한 면을 선호해요.`
- 분석 기준: `23개의 라멘 기록을 기반으로 분석됨`
- 돈코츠, 이에케, 쇼유, 시오 선호도
- 국물 농도
- 면 단단함
- 매운맛
- 토핑 선호
- 최근 취향 변화
- 이번 기록으로 달라진 항목
- 아직 덜 탐색한 스타일
- 다음에 도전할 한 그릇 1개

수치만 나열하지 말고 사람이 이해할 수 있는 문장을 함께 제공한다.

레이더 차트보다 모바일에서 읽기 쉬운 수평 막대와 텍스트 설명을 우선한다.

추천 예시:

`다음에는 깔끔한 시오 라멘을 기록하면 취향의 반대편도 더 정확히 알 수 있어요.`

### 09. Feed / Interest Shop News

기존 관심 가게 소식 화면을 하단 `피드` 탭과 연결한다.

포함할 내용:

- 관심 가게 새 소식
- 한정 메뉴
- 영업시간 변경
- 임시 휴무
- 라오타 유저의 최근 기록
- 필터: 전체, 한정 메뉴, 이벤트, 영업 정보
- 알림 켜기·끄기
- 소식 없음 상태

예시:

`멘야준 · 오늘부터 여름 한정 냉라멘 판매`
`오레노라멘 본점 · 이번 주 영업시간 변경`

이번 프로토타입에서는 커뮤니티 글쓰기와 댓글 기능까지 확장하지 않는다.

────────────────────
5. 핵심 프로토타입 흐름
────────────────────

아래 메인 흐름은 처음부터 끝까지 모두 클릭 가능하게 연결한다.

`홈 추천 카드`
→ `가게 상세`
→ `라멘 기록하기`
→ `20초 기록`
→ `기록 완료`
→ `내 취향 보기`
→ `취향 상세`

보조 흐름:

`지도`
→ `필터 또는 핀 선택`
→ `하단 가게 카드`
→ `가게 상세`

`중앙 + 기록`
→ `기록 진입 바텀시트`
→ `최근 본 가게 선택`
→ `20초 기록`

`기록 완료`
→ `마이`
→ `최근 로그와 기록 수가 갱신된 상태`

화면마다 서로 다른 임시 데이터를 사용하지 말고 같은 사용자와 가게 데이터를 일관되게 이어가야 한다.

공통 데이터:

- 사용자: 뿡님
- 가게: 멘야준
- 위치: 망원
- 메뉴: 특제 쇼유 라멘
- 가격: 13,000원
- 거리: 420m
- 기록 수: 22개 → 저장 후 23개

────────────────────
6. 인터랙션과 모션
────────────────────

- 카드에서 상세로 이동할 때 사진의 맥락이 이어지는 180–220ms 전환
- 바텀시트는 아래에서 약 240ms로 등장
- 탭 전환은 과한 이동 없이 짧은 페이드
- 버튼 누름은 약한 축소와 즉시 색상 변화
- 지도 핀 선택 시 작은 확대와 카드 동기화
- 기록 완료에서는 기록 수, 취향 변화, 인사이트가 한 번만 순차적으로 등장
- confetti, 과도한 bounce, 반복 pulse, 자동 재생 캐러셀은 사용하지 않는다
- reduced motion 환경에서는 이동과 확대를 제거한다

모든 핵심 버튼은 실제 화면 또는 상태 변화와 연결한다. 눌러도 아무 일도 일어나지 않는 장식용 버튼을 만들지 않는다.

────────────────────
7. 필수 상태와 접근성
────────────────────

컴포넌트 또는 화면 variant로 다음 상태를 포함한다.

- 기본
- 눌림
- 선택
- 비활성
- 로딩 스켈레톤
- 빈 상태
- 검색 결과 없음
- 오류와 재시도
- 위치 권한 거부
- 저장 중
- 저장 실패
- 저장 성공
- 긴 가게명과 메뉴명
- 두 줄 이상의 실제 한국어 문장

접근성 기준:

- 모든 터치 영역 최소 44×44px
- 본문 텍스트 14–16px
- 텍스트 대비 WCAG AA
- 빨간색만으로 선택, 오류, 현재 위치를 표현하지 않기
- 아이콘 버튼에 이해할 수 있는 한국어 라벨 제공
- 별점과 취향 점수에 숫자 결과 함께 제공
- 스와이프 외에 명시적인 버튼으로도 같은 행동 제공
- 하단 탭과 고정 CTA가 iOS·Android safe area를 침범하지 않기

────────────────────
8. 최종 결과물
────────────────────

최종 결과는 서로 분리된 정적 시안이 아니라 RAOTA의 핵심 습관 루프가 작동하는 하나의 모바일 앱 프로토타입이어야 한다.

기존 `Mobile HIFI v2`의 인상은 유지하면서 다음을 확장해줘.

- 화면 사이의 연결
- 선택과 저장 상태
- 실패와 복구 상태
- 데이터가 실제로 변경되는 느낌
- 기록 후 얻는 보상
- RAOTA만의 개인 취향 정체성

사용자가 프로토타입을 한 번 사용한 뒤 다음과 같이 느끼게 만들어줘.

`라멘집을 하나 찾았다`가 아니라
`내가 좋아하는 라멘을 조금 더 정확히 알게 됐다.`
